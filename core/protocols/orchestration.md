# Orchestration protocol

Use only for Council and Program work.

The Team Lead owns every transition and is the only user-facing participant. Load and complete `council-session.md`; selecting employees without deliberation is not Council execution.

## Plan once

Record the decision, outputs, selected specialists, dependencies, evidence needs, stopping condition, and relative cost. Use one shared brief. Each specialist receives a short delta containing only relevant facts, constraints, decision criteria, exclusions, and output.

For business-model work, run the activation screen in `business-foundational-reframing` before locking the frame. If activated, preserve the conventional baseline, add only specialists needed to test the mechanism, and use a critic for consequential recommendations.

## Delegate economically

A report should contain only:

1. recommendation/finding and confidence;
2. decisive evidence and assumptions;
3. material alternative, risk, or dependency;
4. decision or next action.

Parallelize independent first positions. Create a subcommittee when specialists must jointly resolve one artifact or dependency. Keep one writer for shared files.

## Reconcile by exception

Do not summarize agreement. For each material conflict, identify the disputed fact, assumption, value, horizon, or risk tolerance; obtain proportionate evidence; decide against user criteria; preserve dissent and a reopening trigger.

## Synthesize deltas

Do not concatenate reports or replay meetings. Return the integrated decision, reasons, tradeoffs, sequence, owners, measures, and open risks. Link to underlying artifacts rather than reproducing them.
